# macOS 原生版 UX 方案

## 目标

将当前桌面版从“功能演示型工具”重构为“高频可用的 macOS 原生工作台”。

核心目标：
- 降低首次使用门槛
- 提升高频对话效率
- 让模型、工具、工作流、日志成为同一条工作流的一部分
- 弱化“诊断面板式 UI”，强化“工作台式 UI”

## 当前主要问题

### 1. 信息架构混乱
- 聊天、设置、诊断、workflow、connector 管理耦合在一起
- 主要操作入口不稳定，用户不知道下一步该去哪
- 工作流、截图、日志等能力存在，但缺少明确归位

### 2. 主路径不顺
- 用户最常见的动作是：提问、切模型、看工具调用、继续追问
- 当前主路径被大量次级信息打断
- 错误提示偏技术化，恢复路径不清晰

### 3. 桌面感不足
- 缺少原生侧边栏、命令菜单、快捷键、窗口层级、状态反馈
- 交互像网页后台，不像 macOS 应用

## 设计原则

### 原则 1：主路径优先
默认界面只服务于 5 个动作：
- 发消息
- 查看回复
- 查看工具动作
- 切会话
- 切模型

### 原则 2：重操作不出主屏
除深度设置外，大部分操作不跳页，不打断当前思路。

### 原则 3：工作台而不是控制台
让用户觉得自己在一个长期工作的桌面环境里，而不是在调试一个 Agent。

### 原则 4：渐进显露复杂度
新手先看到聊天和会话；进阶用户再看到 workflow、日志、截图、上下文、会话检索。

### 原则 5：错误要可恢复
错误提示必须附带“下一步建议”，而不只是 HTTP 状态码或异常文本。

## 顶层信息架构

采用三栏结构。

### 左栏：导航与会话
承担“我在哪”和“我能切到哪”的职责。

包含：
- 应用标题 / 当前工作区
- 新建会话
- 会话列表
- 收藏 / 置顶 / 最近会话
- 搜索会话
- 底部固定入口：设置、工作流、资源库

### 中栏：主对话区
承担“当前任务执行”的职责。

包含：
- 顶部上下文条
  - 当前会话标题
  - 当前模型
  - 当前模式（聊天 / 工作流 / 研究）
  - 快捷操作：切模型、清空上下文、停止生成
- 消息流
  - 用户消息
  - 助手消息
  - 工具动作折叠卡片
  - 错误卡片
  - 工作流运行卡片
- 输入区
  - 文本输入
  - 附件/截图入口
  - 快捷命令提示
  - 发送 / 停止

### 右栏：工作台
承担“辅助当前任务”的职责，不做独立主页面。

采用 Tab/Segment 切换：
- 上下文
- 工具动作
- 工作流
- 日志
- 资源

默认只展开与当前任务相关的内容。

## 右栏模块定义

### 上下文
显示当前轮对话实际带入的信息：
- 当前会话摘要
- 命中笔记
- Web 结果
- 最近工具输出
- 当前 sprint contract / workflow contract

目标：让用户知道模型“看到了什么”。

### 工具动作
展示最近工具链路：
- 调用了什么工具
- 参数是什么
- 返回了什么
- 是否成功
- 是否可重试

不再把工具调用当成聊天正文污染消息流。

### 工作流
展示：
- 工作流列表
- 运行按钮
- 最近运行结果
- Sprint 契约
- 验收状态

工作流仍属于当前任务上下文，而不是单独后台页面。

### 日志
给高级用户：
- command
- tool_call
- progress
- error

默认折叠，不干扰新手。

### 资源
聚合截图、导出、会话归档、当前附件等信息。

## 核心交互流

### 流程 A：普通聊天
1. 用户从左栏选择会话
2. 中栏阅读最近对话
3. 输入新消息
4. 若有工具动作，在消息流中只显示简洁摘要
5. 详细工具过程在右栏“工具动作”中查看
6. 回复完成后，中栏保留结果，右栏同步更新上下文

### 流程 B：切换模型
1. 点击中栏顶部模型标签
2. 弹出原生下拉面板
3. 展示最近模型、已保存 connector、可用状态
4. 切换成功后给出非打断式反馈
5. 若失败，提示原因 + 建议动作

### 流程 C：运行工作流
1. 打开右栏“工作流”
2. 选择 workflow
3. 可填写目标或保持默认
4. 运行后在中栏插入工作流卡片
5. 卡片展示阶段、契约、验收结果
6. 用户可一键将输出转成下一轮聊天上下文

### 流程 D：查看工具失败
1. 中栏显示简短错误卡片
2. 错误卡片包含：失败原因、建议操作、查看详情
3. 详情在右栏“工具动作”/“日志”里展开
4. 用户可选择：重试、换模型、忽略继续

## 关键交互改造点

### 1. 模型切换
当前问题：像配置管理，不像高频操作。

改为：
- 顶部一键切换
- 最近使用优先
- 当前模型状态可视化
- 失败提示直接说明是否是模型名、鉴权、参数、tools 不兼容

### 2. 工具反馈
当前问题：工具调用与正文混杂，用户难以理解。

改为：
- 中栏只显示简洁“动作摘要卡”
- 右栏显示结构化详情
- 工具失败时直接展示恢复建议

### 3. 工作流体验
当前问题：工作流像附加功能。

改为：
- 作为右栏核心模块
- 每次运行都带目标、进度、契约、结果
- 可把运行结果直接回填为聊天上下文

### 4. 设置入口
设置从“诊断感”改成真正的应用设置。

分层：
- 偏好设置：主题、字体、快捷键、默认模型
- 连接设置：connector / provider
- 工作区设置：vault、skills、workflow roots
- 高级设置：日志、调试、实验特性

### 5. 会话系统
会话要更像真正的工作空间：
- 支持 pin / archive / favorite
- 支持会话搜索
- 支持分组（研究 / 开发 / 日常）
- 支持快速克隆会话

## 原生 macOS 交互要求

### 菜单栏
提供：
- New Chat
- Search Sessions
- Switch Model
- Run Workflow
- Capture Screenshot
- Export Session
- Open Settings

### 快捷键
建议默认：
- `Cmd+N`：新建会话
- `Cmd+K`：全局命令面板
- `Cmd+1`：聚焦左栏
- `Cmd+2`：聚焦主对话区
- `Cmd+3`：切换右栏
- `Cmd+,`：设置
- `Cmd+Enter`：发送
- `Esc`：停止生成 / 关闭浮层

### 原生体验细节
- 支持侧边栏折叠
- 支持多窗口（后续）
- 支持拖入文件/图片
- 支持系统分享/导出
- 支持空状态引导
- 支持 skeleton/loading 状态

## MVP 范围

第一版原生 MVP 只做：
- 三栏工作台
- 会话管理
- 聊天主流程
- 模型切换
- 工具动作面板
- 工作流运行面板
- 基础设置
- 错误恢复提示

暂不优先：
- 多窗口协同
- App Store 发布
- 完整主题系统
- 复杂动画
- 全量调试面板

## 交付建议

### 第 1 阶段
输出：
- 交互图
- 页面结构图
- 模块边界
- 状态流说明

### 第 2 阶段
落地：
- SwiftUI 原生骨架
- 三栏布局
- 会话 / 聊天 / 模型切换主路径

### 第 3 阶段
补齐：
- 工作流
- 工具动作
- 日志
- 设置

## 实施判断

这不是“界面换皮”，而是：
- 重新定义产品主路径
- 重新定义复杂度暴露方式
- 让 Agent 产品像真正的 macOS 工作台

后续实现阶段应以该文档作为交互基线，围绕原生 macOS 工作台继续迭代。
