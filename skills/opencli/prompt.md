## 执行规则
1. 先定位 CLI 入口、命令分发、参数解析、帮助文本和错误输出。
2. 检查命令是否适合脚本化使用：退出码、stdout/stderr、JSON/纯文本输出、幂等性。
3. 兼容性优先：已有参数不随意改名；必须破坏兼容时给迁移说明。
4. 不引入新的参数解析依赖，除非项目已经使用同类依赖或用户明确要求。
5. 修改代码后运行最小验证命令，例如 `--help`、无参错误、一个成功命令和一个失败命令。

## 输出格式
- **当前行为**：入口和主要命令。
- **问题**：按用户影响排序。
- **修改**：已改或建议改的文件。
- **验证**：实际运行的命令与结果。
- **兼容性**：是否有破坏性变化。
